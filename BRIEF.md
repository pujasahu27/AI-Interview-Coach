# AI Interview Coach — Project Brief

## Idea

An AI-powered mock interview web app. A user uploads a resume and a job description, enters their years of experience, and the app runs a voice-based mock interview that adapts question-by-question based on their answers. Each answer is evaluated, and at the end the user gets personalized learning recommendations.

## Key Constraints

- **No budget** — this is an experimental/personal project. Use the **Gemini API** (free-tier "flash" model) instead of paid providers, and the browser-native **Web Speech API** for voice instead of paid STT/TTS services.
- **Voice-based interview**, not just text — questions are spoken aloud (TTS) and answers are spoken by the user (STT), with a text fallback for unsupported browsers.
- **Adaptive follow-up questions** — not a fixed question bank. Each next question depends on the evaluation of the prior answer (probe deeper on weak points, move on from strong ones).
- **Proper account login** (Firebase Auth) with a limited number of free interview turns per user, then a paywall.

## Onboarding Flow

**1. First-time account setup** (once, right after signup, before dashboard) — skippable:
- Full name
- Target role / job title (e.g. "Backend Engineer")
- Years of experience (default, editable later per session)
- Preferred interview focus: Behavioral / Technical / Mixed (default, editable later)

Stored on `users/{uid}` as `displayName`, `targetRole`, `defaultYearsOfExperience`, `defaultInterviewFocus`.

**2. Pre-interview intake form** (every session, on `/dashboard`):
- Resume: upload PDF/DOCX or paste text (can reuse last resume)
- Job description: paste text or upload, specific to this session
- Years of experience: pre-filled from profile, editable
- Interview focus: pre-filled from profile, editable
- "Start Interview" → creates the session

`interviewFocus` feeds into the Gemini prompt as an extra parameter (e.g. steer toward STAR-style behavioral questions vs role-specific technical questions vs a mix).

## MVP Feature List

**Must-have:**
1. Firebase Auth (email/password + Google sign-in), auth-gated app shell
2. First-time profile setup (skippable, one-time)
3. Resume + JD upload/paste + years of experience + interview focus, parsed server-side (pdf-parse / mammoth) and stored in Firestore
4. First interview question generated by Gemini from resume + JD + years of experience
5. Adaptive loop: spoken question (SpeechSynthesis) → spoken answer (SpeechRecognition, text fallback) → Gemini evaluates (score, strengths, gaps) → Gemini generates the next question from the running transcript + gaps — repeats until max turns or user ends session
6. Per-turn evaluation stored and shown to the user
7. End-of-session personalized learning recommendations (aggregated gaps → study pointers)
8. Usage credits: N free turns per user, enforced server-side; paywall screen once exhausted (stub upgrade button, no real billing yet)

**Explicitly deferred (post-MVP):** real Stripe billing, session history/dashboard, multiple interview tracks, resume-improvement suggestions (separate from interview gaps), PDF export, admin usage dashboard, non-Chrome STT fallback via a server-side model, multi-language support.

## Architecture

**Stack:** Next.js (App Router) + Firebase (Auth, Firestore, Storage — Spark/free plan) + Gemini API (flash-tier model).

All Gemini calls and credit mutations happen **server-side only** (Next.js API routes + Firebase Admin SDK) — protects the API key and prevents paywall bypass.

```
/app
  /login/page.tsx
  /dashboard/page.tsx                      → upload resume/JD, start interview
  /interview/[sessionId]/page.tsx          → live voice interview loop
  /interview/[sessionId]/summary/page.tsx  → recommendations
  /paywall/page.tsx                        → stub upgrade page

  /api/upload-resume/route.ts              → parse PDF/DOCX server-side
  /api/interview/start/route.ts            → create session, generate first question
  /api/interview/[sessionId]/turn/route.ts → credit gate + evaluate answer + generate next question (combined Gemini call)
  /api/interview/[sessionId]/end/route.ts  → aggregate evaluations, generate recommendations

/lib
  firebase-admin.ts   → Admin SDK init, ID-token verification
  firebase-client.ts  → client SDK init (Auth, Firestore listeners)
  gemini.ts           → Gemini client + prompt builders
  parsing.ts          → pdf-parse / mammoth wrappers
  credits.ts          → transactional credit-check/decrement

/components
  VoiceRecorder.tsx   → wraps SpeechRecognition, text fallback
  QuestionPlayer.tsx  → wraps SpeechSynthesis
  ResumeUploader.tsx
  SessionSummary.tsx
```

**Voice I/O:** entirely client-side and free — `window.speechSynthesis` for TTS, `webkitSpeechRecognition` for STT (Chrome/Edge), textarea fallback on Safari/Firefox.

**Cost control:** Gemini flash-tier model only; combine per-turn evaluation + next-question into a single call; cap max turns per session (6–8); keep per-user free-turn limit low (15–20) as a natural rate limiter. Stay on Firebase Spark plan (no billing account) — keep all server logic in Next.js API routes rather than Cloud Functions.

## Firestore Data Model

```
users/{uid}                     → email, displayName, targetRole, defaultYearsOfExperience, defaultInterviewFocus, freeTurnsUsed, freeTurnsLimit, plan
resumes/{resumeId}              → uid, rawText, jobDescriptionText, yearsOfExperience, interviewFocus
interviewSessions/{sessionId}   → uid, resumeId, status, turnCount, maxTurns, recommendationsSummary, overallScore
interviewSessions/{sessionId}/turns/{turnId} → question, answerTranscript, evaluation{score, strengths, gaps, notes}
```

Credit fields live directly on `users/{uid}` for MVP simplicity.

## Adaptive Interview Loop (one turn, end to end)

1. **Start:** `/api/interview/start` prompts Gemini with resume + JD + years of experience → opening question → stored as `turns/0`.
2. **Answer:** question is spoken (TTS); user records a spoken answer (STT) → transcript reviewed/edited → submitted.
3. **Turn:** `/api/interview/[sessionId]/turn` checks the credit gate first (paywall if exhausted), then sends one combined Gemini prompt (question + answer + resume/JD + prior transcript) → gets back `{evaluation, nextQuestion}` → writes new turn doc, increments `turnCount`, decrements credits, all in one Firestore transaction.
4. **End:** session ends at `turnCount >= maxTurns`, manual end, or credits exhausted. `/api/interview/[sessionId]/end` aggregates evaluations and generates a recommendations summary.

## Phased Build Order

1. **Foundation** — Firebase setup, Auth, resume/JD upload UI + server-side parsing into Firestore
2. **Single question generation** — Gemini wiring, `/api/interview/start`, first question as plain text (validate prompt quality before adding voice)
3. **Adaptive loop + voice** — `VoiceRecorder`/`QuestionPlayer`, `/api/interview/[sessionId]/turn`, full multi-turn loop
4. **Evaluation + recommendations** — per-turn scores/gaps UI, `/api/interview/[sessionId]/end`, summary page
5. **Credits/paywall** — credit fields, transactional gate, stub `/paywall` page

Each phase is independently demoable.

## Verification Plan

- Phase 1: sign in, upload a real resume PDF + paste a JD, confirm parsed text in Firestore.
- Phase 2: confirm generated question is relevant across 2-3 different resume/JD combos.
- Phase 3: full voice interview in Chrome; text-fallback path in Firefox/Safari; confirm each next question meaningfully follows the prior answer.
- Phase 4: confirm summary recommendations match the gaps actually surfaced per turn.
- Phase 5: confirm paywall triggers exactly at the free-turn limit and credit decrement can't be bypassed by calling the API directly.
